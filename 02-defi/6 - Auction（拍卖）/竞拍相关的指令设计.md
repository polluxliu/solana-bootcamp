# 竞拍相关的指令设计

# 英式拍卖

在英式拍卖中，出价逐步抬高，新出价必须高于当前最高出价，上一个最高出价人得到全额退款。拍卖临近结束时若有人出价，系统自动延长时间，保证公平竞争。

## 竞拍指令的账户上下文

```rust
#[derive(Accounts)]
pub struct PlaceBid<'a> {
    // 拍卖行
    pub auction_house: Account<'a, AuctionHouse>,

    // 拍卖活动账户
    #[account(
        mut,
        has_one = auction_house
    )]
    pub auction: Account<'a, Auction>,

    // 出价资金托管账户
    #[account(
        mut,
        address = auction.escrow_bid_ta @ error::ErrorCode::InvalidEscrowBidAccount
    )]
    pub escrow_bid_ta: Account<'a, TokenAccount>,

    // 出价人
    #[account(mut)]
    pub bidder: Signer<'a>,

    // 出价人结算代币 ATA
    pub bidder_ata: Account<'a, TokenAccount>,

    // 上一个最高出价人结算代币 ATA，用于将资金退还
    #[account(mut)]
    pub refund_ata: Account<'a, TokenAccount>,

    // SPL Token Program
    pub token_program: Program<'a, Token>,
}
```

在 `auction` 账户中，字段 `escrow_bid_ta`存储了出价资金托管账户的公钥 ，字段 `highest_bidder` 存储了当前最高出价者（也就是 `refund_ata`）的公钥，但我们依然需要把 `escrow_bid_ta` 和 `refund_ata` 这两个账户作为账户上下文传入，是因为在 Solana on-chain 程序中，无法凭 Pubkey 读取账户。

在一次交易执行时，**前端必须把所有要用到的账户都传入**。而在 off-chain 客户端（比如你的前端、脚本）中，可以用 `connection.getAccountInfo(pubkey)` 去 RPC 节点获取到账户。

## 竞拍指令

```rust
pub fn hander(ctx: Context<PlaceBid>, bid_amount: u64) -> Result<()> {
    // 不可变借用 auction 来校验
    let auction = &ctx.accounts.auction;

    // 0. 拍卖必须是英式拍卖
    require!(
        auction.auction_type == 0,
        error::ErrorCode::InvalidAuctionType
    );

    // 1. 校验拍卖是否进行中
    let now = Clock::get()?.unix_timestamp;
    require!(
        now >= auction.start_time,
        error::ErrorCode::AuctionNotStarted
    );
    require!(now < auction.end_time, error::ErrorCode::AuctionEnded);

    // 2. 校验出价必须高于当前最高价
    require!(
        bid_amount > auction.english_highest_bid,
        error::ErrorCode::BidTooLow
    );

    // 3. 校验传入的 refund_ata 是否是 (highest_bidder, settlement_mint) 对应的 ATA。
    // 这样可以确保退款时资金只会退回给上一个最高出价人的正确结算代币账户，避免攻击者传入任意账户地址。
    // 只有在已有最高出价时才需要校验 refund_ata
    if auction.english_highest_bid > 0 {
        require!(
            ctx.accounts.refund_ata.key()
                == get_associated_token_address(
                    &auction.english_highest_bidder,
                    &ctx.accounts.auction_house.settlement_mint
                ),
            error::ErrorCode::InvalidRefundTokenAccount
        );
    }

    // 4. 扣除出价资金 → 转入托管账户
    let cpi_accounts = Transfer {
        from: ctx.accounts.bidder_ata.to_account_info(),
        to: ctx.accounts.escrow_bid_ta.to_account_info(),
        authority: ctx.accounts.bidder.to_account_info(), // 竞拍人
    };
    transfer(
        CpiContext::new(ctx.accounts.token_program.to_account_info(), cpi_accounts),
        bid_amount,
    )?;

    // 5. 如果已有最高价 → 退还给上一个出价人
    if auction.english_highest_bid > 0 {
        let cpi_accounts = Transfer {
            from: ctx.accounts.escrow_bid_ta.to_account_info(),
            to: ctx.accounts.refund_ata.to_account_info(),
            authority: ctx.accounts.auction.to_account_info(), // auction PDA
        };
        // 构造 signer seeds
        let auction_id_bytes = auction.auction_id.to_le_bytes();
        let seeds = &[
            b"auction",
            auction.auction_house.as_ref(),
            auction_id_bytes.as_ref(),
            &[auction.bump],
        ];
        let signer_seeds = &[&seeds[..]];
        transfer(
            CpiContext::new_with_signer(
                ctx.accounts.token_program.to_account_info(),
                cpi_accounts,
                signer_seeds,
            ),
            auction.english_highest_bid,
        )?;
    }

    // 可变借用 auction 来更新
    let auction = &mut ctx.accounts.auction;

    // 6. 更新最高出价和出价人
    auction.english_highest_bid = bid_amount;
    auction.english_highest_bidder = ctx.accounts.bidder.key();

    // 7. 软结束逻辑：如果在最后 60s 出价 → 延长 60s（不超过 final_end_time）
    let remaining = auction.end_time - now;
    if remaining <= 60 {
        let new_end_time = auction.end_time + 60;
        auction.end_time = std::cmp::min(new_end_time, auction.end_time_deadline);
    }

    // 8. 触发事件
    emit!(BidPlaced {
        auction: auction.key(),
        bidder: ctx.accounts.bidder.key(),
        bid_amount,
        end_time: auction.end_time, // 出价后更新过的最新截止时间
    });

    Ok(())
}
```

- `Transfer<'a>`
    
    `Transfer<'info>` 是 **SPL Token Program 的 Transfer 指令账户集合**，它里面引用的账户都活得和 `'info` 一样久。
    
    ```rust
    pub struct Transfer<'info> {
        pub from: AccountInfo<'info>,
        pub to: AccountInfo<'info>,
        pub authority: AccountInfo<'info>,
    }
    ```
    
- `CpiContext`
    
    Anchor 框架中用于构建跨程序调用（Cross Program Invocation，CPI）的上下文结构体，它将调用目标程序所需的信息集中起来，方便进行程序之间的互操作。
    
    ```rust
    pub struct CpiContext<'a, 'b, 'c, 'info, T> {
        pub accounts: T,
        pub remaining_accounts: Vec<AccountInfo<'info>>,
        pub program: AccountInfo<'info>,
        pub signer_seeds: &'a [&'b [&'c [u8]]],
    }
    ```
    
    - `accounts: T`
        
        泛型 `T` 代表这次调用需要的所有账户集合。
        
    - `remaining_accounts: Vec<AccountInfo<'info>>`
        
        额外的账户列表。用来传递那些程序需要但不在主要指令账户结构体里定义的额外账户。这些账户通常是：
        
        - 无法在指令的账户结构体中静态定义的
        - 程序执行时确实需要，但数量或类型可能会变化
        - 需要在执行过程中动态访问的
        
        为什么需要 `remaining_accounts`？有些场景下你需要传递一些账户，它们可能：
        
        - 数量可变（编译时不知道会有多少个）
        - 有时可选（某些情况下需要，某些情况下不需要）
        - 不适合放进主账户结构体
        - 复杂逻辑中需要更灵活的账户访问方式
    - `program: AccountInfo<'info>`
        
        被调用的目标程序的账户信息。
        
    - `signer_seeds: &'a [&'b [&'c [u8]]]`
        
        **钱包账户** 有私钥，可以直接签名。而 **PDA (Program Derived Address)** 没有私钥，所以它不能像用户钱包一样直接签名，但很多场景需要 PDA 作为 **authority**，比如 Token Account 的 owner，这时 Solana 运行时会通过 **链上校验** 来确认该 PDA 是否是合法的。
        
        1. 传入的 `signer_seeds` 包含 seeds + bump。
        2. runtime 用这些参数重新调用
            
            `Pubkey::create_program_address(seeds + bump, program_id)`
            
        3. 如果生成的结果和你提供的 PDA 公钥相等，则认定这个 PDA 是有效的 signer。

        💡
        
        PDA 的 **签名** 其实是 **链上的地址一致性校验**，而不是密码学意义上的签名。

        `&'a [&'b [&'c [u8]]]`
        
        我们去掉生命周期标识，仅分析 `&[&[&[u8]]]`：
        
        - `&[u8]`：是一个对元素类型为 `u8` 的切片类型的引用。常用来表示某个字节数组的只读视图，如 `b"auction"`。每个 `&[u8]` 就是一个 seed。
        - `&[&[u8]]`：也是一个切片类型的引用，切片里每个元素都是 `&[u8]`，存放多个 `&[u8]`。每个 `&[u8]` 是一个 seed，而多个 seed 拼在一起就是 PDA 的 seeds。
        - `&[&[&[u8]]]`：也是一个切片类型的引用，存放多个 `&[&[u8]]`。每个 `&[&[u8]]` 是一个 PDA 的 seeds，那这里就表示多个 PDA 的 seeds。因为一次 CPI 调用可能需要多个 PDA 的签名。
        
        为了便于理解 `signer_seeds` 的类型，我们拆解开来看：
        
        ```rust
        let x1 : &[u8;7] = b"auction";
        let x2 : &[u8] = auction.auction_house.as_ref();
        let x3 : &[u8] = auction_id_bytes.as_ref();
        let x4 : &[u8;1] = &[auction.bump];
        
        let x : &[&[u8];4] = &[x1, x2, x3, x4];
        
        let y : &[&[u8]] = &x[..];
        ```
        
        `&[u8; 7]`：是一个对元素类型为 `u8` 且长度为 `7` 的数组的引用。
        
        - **类型里包含了长度信息**（7）。
        - 编译器在编译时就能知道这是长度为 7 的数组引用。
        
        `&[u8]`：是一个对切片类型 `[u8]` 的引用。
        
        - **类型里不包含长度信息**。
        - 只表示某段 `u8` 序列的引用，至于这段序列长度是多少，只有在运行时才知道。
        - `&[u8]` 本身是 **一个胖指针**，编译器知道 `&[u8]` **这个引用的大小**，它的大小在编译期是固定的。
            - 在 64 位系统里，`&[u8]` 占 16 字节：
                - 8 字节：数据起始地址
                - 8 字节：切片长度
            
            至于它指向的数据有多长，不需要在编译期确定，运行时就可以知道。
            
        
        `let x : &[&[u8];4] = &[x1, x2, x3, x4];`
        
        `x` 是一个对元素为 `&[u8]` 类型且长度为 `4` 的数组的引用。
        
        Rust 在推导数组类型时，要求所有元素类型一致，根据这 4 个元素的类型，自动把它们统一转换为最一般的类型 `&[u8]`，所以编译器会对 `x1` 和 `x4` 做 **切片强制转换**：
        
        - `&[u8; 7]` → `&[u8]`
        - `&[u8; 1]` → `&[u8]`
        
        `let y : &[&[u8]] = &x[..];`
        
        `[..]` 创建一个指向数组的一部分（或全部）的视图，即切片。
        
        `x[..]`：
        
        - Rust 会先对 `x` 自动解引用，得到数组值 `[&[u8]; 4]`。
        - 然后对数组做 `[..]` 切片操作，结果类型是 `[&[u8]]`。
        
    - `'a, 'b, 'c, 'info`
        
        生命周期标识，确保引用的账户和种子在调用期间有效。
        

# 荷兰拍卖

在荷兰拍卖中，买家在任何时刻都可以按当前动态价格买断拍品，支付资金后，拍卖立即结束并记录成交信息。如果没有买家出手，拍卖会在 `end_time` 过后流拍。在价格下降过程中，价格降到最低的 `dutch_end_price` 后将不再降价。

## 竞拍指令的账户上下文

```rust
#[derive(Accounts)]
pub struct BuyNow<'a> {
    // 拍卖行
    pub auction_house: Account<'a, AuctionHouse>,

    // 拍卖活动账户
    #[account(
        mut,
        has_one = auction_house
    )]
    pub auction: Account<'a, Auction>,

    // 出价资金托管账户
    #[account(
        mut,
        address = auction.escrow_bid_ta @ error::ErrorCode::InvalidEscrowBidAccount
    )]
    pub escrow_bid_ta: Account<'a, TokenAccount>,

    // 买家
    #[account(mut)]
    pub buyer: Signer<'a>,

    // 买家结算代币 ATA
    pub buyer_ata: Account<'a, TokenAccount>,

    // SPL Token Program
    pub token_program: Program<'a, Token>,
}
```

## 竞拍指令

```rust
pub fn handler(ctx: Context<BuyNow>) -> Result<()> {
    let auction = &mut ctx.accounts.auction;

    // 0. 校验：拍卖必须是荷兰拍卖
    require!(
        auction.auction_type == 1,
        error::ErrorCode::InvalidAuctionType
    );

    // 1. 校验：拍卖必须正在进行
    let now = Clock::get()?.unix_timestamp;
    require!(
        now >= auction.start_time,
        error::ErrorCode::AuctionNotStarted
    );
    require!(
        now < auction.end_time,
        error::ErrorCode::AuctionEnded
    );

    // 2. 校验：拍卖未成交过
    require!(auction.status.is_none(), error::ErrorCode::AuctionEnded);

    // 3. 计算当前价格
    let elapsed = now.saturating_sub(auction.start_time); // 已经过的秒数
    let steps = (elapsed / auction.dutch_price_drop_interval) as u64; // 已经降了多少次

    let total_drop = steps
        .checked_mul(auction.dutch_price_drop_amount)
        .ok_or(error::ErrorCode::NumericalOverflow)?; // 价格下降的幅度

    let mut current_price = auction.start_price.saturating_sub(total_drop); // 当前价格
    if current_price < auction.dutch_end_price {
        current_price = auction.dutch_end_price;
    }

    // 4. 买家支付资金到托管账户
    let cpi_accounts = Transfer {
        from: ctx.accounts.buyer_ata.to_account_info(),
        to: ctx.accounts.escrow_bid_ta.to_account_info(),
        authority: ctx.accounts.buyer.to_account_info(),
    };
    transfer(
        CpiContext::new(ctx.accounts.token_program.to_account_info(), cpi_accounts),
        current_price,
    )?;

    // 5. 更新拍卖状态
    auction.status = Some(AuctionStatus::Settled);
    auction.final_price = current_price;
    auction.buyer = ctx.accounts.buyer.key();

    // 6. 触发事件
    emit!(Bought {
        auction: auction.key(),
        buyer: ctx.accounts.buyer.key(),
        price: current_price,
    });

    Ok(())
}
```

荷兰拍卖的关键点就是：**价格与时间强绑定**。

**价格是时间函数**，拍卖价格是由 **起始价格**、**时间间隔**、**每次下降幅度** 和 **最低价** 计算出来的。合约中 **不存储实时价格**，而是根据区块链的时间戳随时算出来。荷兰拍卖价格计算逻辑如下：

- **确定已过时间**
    
    当前区块时间减去拍卖开始时间，得到已经过去的秒数。
    
- **计算下降次数**
    
    用已过时间除以价格下降的时间间隔，得到价格已经下降了多少次。
    
- **计算总下降幅度**
    
    每次下降的幅度乘以下降次数，得到价格从起始价已经下降的总数额。
    
- **得到当前价格**
    
    起始价格减去总下降幅度，得到当前的价格。
    
- **设置价格下限**
    
    如果计算出的价格低于预设的最低价，就强制把当前价格设为最低价。
