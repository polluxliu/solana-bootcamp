# 平台相关的账户模型和指令设计

# 平台配置

## 账户模型

```rust
#[account]
#[derive(InitSpace)]
pub struct Platform {
    // 平台管理员公钥
    pub authority: Pubkey,

    // 一次性收取的拍卖行创建费
    pub auction_house_creation_fee: u64,

    // 平台抽成费率，以 basis points 为单位
    pub platform_fee_rate: u16,

    // 最小的拍卖持续时间，以秒为单位
    pub auction_duration_min: u64,

    // 最大的拍卖持续时间，以秒为单位
    pub auction_duration_max: u64,

    // 平台创建时间戳，以秒为单位
    pub created_at: i64,

    // PDA bump
    pub bump: u8,
}
```

`authority: Pubkey`

平台管理员地址。只有 `authority` 才能执行平台级的受限操作（如更新费率、调整拍卖时长边界、添加/移除支持代币、修改金库地址等）。

`auction_house_creation_fee: u64`

创建拍卖行（Auction House）的一次性费用。筛选认真参与者并补贴平台运营。若平台生态要支持零费用，允许为 0。

`platform_fee_rate: u16`

平台抽成费率，使用基点（basis points） 表示，其取值范围是 `0..=10000`（上限 100%）。Basis Point 是一种表示百分比的单位，区块链和金融系统里一般避免使用浮点数，用整数更安全。`1个基点 = 0.01%`。

`auction_duration_min: u64`

允许的最短拍卖时长（单位：秒）。防止恶意发起过短拍卖（例如 1 秒）。如果有人故意设置极短时间，买家几乎来不及看到并出价，只有发起人自己或者“脚本党 / 机器人”能提前准备好，这很可能是为了规避市场竞争、甚至做利益输送（例如自己小号竞拍）。

`auction_duration_max: u64`

允许的最长拍卖时长（单位：秒）。每一个拍卖活动对应一个账户，里面保存了拍品信息、出价状态等。如果一个拍卖时间设置得特别长（比如几个月甚至几年），这个账户就必须长期存在，始终占用着租金和链上存储资源。另外在竞拍时，买家的资金和卖家的拍品都锁在合约里，如果拍卖时长太长，意味着买家的资金和卖家的资产都被长期锁定，无法在市场中流转。

`created_at: i64`

平台创建的绝对时间戳（单位：秒）。其值为 `Clock::get()?.unix_timestamp`，该值为 `i64` 类型，所以这里也使用 `i64` 以与系统保持一致。而上面的拍卖时长则使用 `u64`，表达非负语义。

`bump: u8`

与平台账户 PDA 绑定的 `bump` 种子。`bump` 的初始值由 Anchor 通过 `find_program_address` 求得，并保存在 `ctx.bumps` 中。后续使用 `seeds + bump` 这个约束的时候，会自动校验该 PDA，防止调用者伪造账户地址。尽管 Anchor 在校验阶段也是可以再次自动找出 bump 的值（只写 `bump` ），但是将该值存储在账户的字段中的话，后续可通过 `bump = some_value` 直接使用该值。

## 平台创建指令的账户上下文

```rust
#[derive(Accounts)]
pub struct InitializePlatform<'a> {
    #[account(
        init,
        payer = authority,
        space = 8 + Platform::INIT_SPACE,
        seeds = [b"platform"],
        bump
    )]
    pub platform: Account<'a, Platform>,

    #[account(mut)]
    pub authority: Signer<'a>,

    pub system_program: Program<'a, System>,
}
```

`#[derive(Accounts)]`

让 Anchor 为该结构体自动生成 **账户校验** 与 **解包 / 打包** 代码。也就是说，交易把一堆账户地址传进来后，Anchor 会按你在每个字段上写的约束（如 `init`、`seeds`、`bump`、`mut` 等）逐个检查，检查通过后把底层 `AccountInfo` 反序列化成你声明的类型，最后把这个结构体交给指令处理器。在指令处理器返回 `Ok(())` 后，把修改的账户序列化回链上。

`pub struct InitializePlatform<'a> { ... }`

定义一条名为 `InitializePlatform` 的账户上下文结构体，供 `initialize_platform` 指令使用。

`pub platform: Account<'a, Platform>` 

要新建的平台状态账户。

- `init` 表示在本次指令里创建该账户
- `payer = authority` 指定由 `authority` 钱包为新账户支付租金与创建费
- `space = 8 + Platform::INIT_SPACE` 设定账户所需字节数，其中 `8` 是 Anchor 的账户 discriminator，`Platform::INIT_SPACE` 是你的结构体数据长度
- `seeds = [b"platform"]` 配合 `bump` 说明这是一个 PDA（程序派生地址），仅用固定字节串作为种子，意味着**全局只允许一个 Platform 实例**（单例模式）
- `bump` 让 Anchor 自动寻找一个 `0..=255` 的校验字节，保证 PDA 落在不可由私钥控制的地址空间
- `Account<Platform>` 是字段类型，表示该账户由你的程序拥有、并反序列化为 `Platform` 结构体。

`pub authority: Signer<'a>` 

平台管理员的钱包账户。

- `Signer` 要求这次交易使用该地址签名。
- `mut` 是因为作为 `payer` 支付租金/手续费时，系统程序会修改其 lamports 余额，所以必须是可写账户。

`pub system_program: Program<'a, System>`

系统程序句柄。创建账户、分配空间、转移 SOL 等系统级操作都需要把 System Program 作为 CPI 目标传入。Anchor 会检查传入的这就是系统程序的可执行账户。

## 平台创建指令

```rust
pub fn handler(ctx: Context<InitializePlatform>, args: InitializePlatformArgs) -> Result<()> {
    // 检查 平台费率是否在 25 ~ 1000 bp（即 0.25% ~ 10%）之间
    require!(
        args.platform_fee_rate >= 25 && args.platform_fee_rate <= 1000,
        error::ErrorCode::InvalidFeeRate
    );
    // 检查 最小拍卖时间是否大于等于 300 秒（5 分钟）。
    require!(
        args.auction_duration_min >= 300,
        error::ErrorCode::AuctionDurationTooShort
    );
    // 检查 最大拍卖时间是否小于等于 2_592_000 秒（= 30 天）。
    require!(
        args.auction_duration_max <= 2_592_000,
        error::ErrorCode::AuctionDurationTooLong
    );
    // 确保最小时长 < 最大时长，避免参数逻辑冲突。
    require!(
        args.auction_duration_min < args.auction_duration_max,
        error::ErrorCode::InvalidDurationRange
    );

    // 从 ctx.accounts 中取出 platform 账户的可变引用。
    let platform = &mut ctx.accounts.platform;

    // 把调用指令的 authority（平台管理员/创建者）地址存入 platform.authority 字段。
    platform.authority = ctx.accounts.authority.key();
    // 把 treasury 的公钥（平台资金库地址）存入 platform.treasury。
    platform.treasury = ctx.accounts.treasury.key();

    // 存储创建 platform PDA 时用到的 bump 值。
    platform.bump = ctx.bumps.platform;

    // 使用系统变量 Clock 读取当前链上时间（Unix 时间戳，秒）。
    platform.created_at = Clock::get()?.unix_timestamp;

    // 把指令传入的参数逐一写入 platform 状态账户。
    platform.auction_house_creation_fee = args.auction_house_creation_fee;
    platform.platform_fee_rate = args.platform_fee_rate;
    platform.auction_duration_min = args.auction_duration_min;
    platform.auction_duration_max = args.auction_duration_max;

    // 触发事件
    emit!(PlatformInitialized {
        authority: platform.authority,
        treasury: platform.treasury,
        platform_fee_rate: platform.platform_fee_rate,
        auction_duration_min: platform.auction_duration_min,
        auction_duration_max: platform.auction_duration_max,
        created_at: platform.created_at,
    });

    Ok(())
}
```

`ctx: Context<InitializePlatform>`

包含了调用这个指令时传入的账户集合（经过 Anchor 验证/反序列化）。

`args: InitializePlatformArgs`

调用时客户端传入的参数（通过 Borsh 反序列化已经转换为 Rust 结构体）。

`Result<()>`

表示可能报错（返回错误码），也可能成功（返回 `Ok(())`）。

`require!(condition, ErrorCode::SomeError)`

Anchor 提供的宏，用于参数检查。

`condition`：布尔表达式。

- 如果 `condition == true` 则继续执行。
- 如果 `condition == false` 则立即返回 `Err(ErrorCode::SomeError.into())`。

`platform.bump = ctx.bumps.platform` 

存储创建 `platform` PDA 时用到的 `bump` 值，这样后续再访问该 PDA 时，可以直接复用这个值。

`platform.created_at = Clock::get()?.unix_timestamp`

使用系统变量 `Clock` 读取当前链上时间（Unix 时间戳，秒）。`?` 表示如果 `Clock::get()` 出错，就提前返回错误。

`Ok(())`

函数执行成功。Anchor 会在 handler 退出后自动把修改过的 `platform` 重新序列化写回链上账户。

`msg!`

这是 Solana runtime 提供的专门日志宏。`msg!` 的输出会被写入到 **交易日志（transaction logs）** 中。你在本地跑 `anchor test` 或在区块浏览器里看某个交易的日志，里面都能看到 `msg!` 打印的内容。因为这些日志属于交易元数据的一部分，客户端和区块浏览器都能读取。

`emit!`

`msg!` 用来给开发者看，`emit!` 用来给外部系统或客户端订阅和解析。

`println!`

这是 Rust 宏，会把字符串写到 **标准输出 stdout**。Solana 程序（BPF 合约）在链上执行时，完全隔离在 BPF 沙盒里，没有标准输出 stdout。所以你即便写了 `println!`，在真实的 on-chain 指令执行时，什么都不会显示。

`InitializePlatformArgs`

```rust
#[derive(AnchorSerialize, AnchorDeserialize)]
pub struct InitializePlatformArgs {
    pub auction_house_creation_fee: u64,
    pub platform_fee_rate: u16,
    pub auction_duration_min: u64,
    pub auction_duration_max: u64,
}
```

在 handler 里直接写很多参数，可读性很差，因此把指令参数单独写成一个 `struct`，这在 Anchor 程序里是很常见的方式。

`#[derive(AnchorSerialize, AnchorDeserialize)]`

一个派生（derive）宏，让 Rust 自动为这个结构体实现一些常见 trait。这里实现的是 `AnchorSerialize/AnchorDeserialize`，它们是 Anchor 框架中定义的两个 trait，基于 Borsh 进行封装，用于对数据结构实现序列化和反序列化功能。Anchor 指令的参数都需要具备这两个 trait。

`PlatformInitialized`

通过 `emit!` 触发一个事件，把结构体序列化后写进 `logMessages`，这是 Solana runtime 在执行合约指令时生成的日志，包括 `msg!` 打印和 `#[event]` 序列化的 JSON。当事件被触发时，客户端回调函数会拿到事件数据。

事件用 Rust 结构体并加上 `#[event]` 进行定义。

```rust
#[event]
pub struct PlatformInitialized {
    pub authority: Pubkey,
    pub treasury: Pubkey,
    pub platform_fee_rate: u16,
    pub auction_duration_min: u64,
    pub auction_duration_max: u64,
    pub created_at: i64,
}
```

# 平台支持的代币

平台需要控制支持哪些代币结算，否则可能有人恶意用垃圾 Token 当货币，骗取拍品。是平台层面对 **允许使用哪些代币作为结算货币** 的白名单。在创建 Auction House 时，必须从中选择一个作为结算代币。

结算（Settlement）就是把 **权利与资金** 落到实处的那一刻：

- 买家把钱（对价资产）支付到位
- 卖家把拍品（标的资产）转移给买家
- 平台/拍卖行收取抽成或手续费
- 剩余资金分配给卖家

结算代币 (Settlement Token) 就是用于结算的货币单位。

- 如果用 SOL，当 SOL 价格剧烈波动，买卖双方承担风险。
- 如果用 USDC，价值稳定，更适合大额交易。

平台用于收取收取创建费和抽成费等的资金库，需要和结算代币进行联动，资金库需要能接收不同的结算代币，为此我们将采用多资金库的设计，为平台所支持的每一种结算代币创建一个 Token Account。我们将为 platform account 创建其所拥有的每一种结算代币的 ATA。注意，这里不能使用平台的管理员（authority）的 ATA，因为 authority 有私钥，能够绕过合约直接操作 ATA，我们需要的是 **平台资金库只能由合约逻辑操作**。

#[account]
#[derive(InitSpace)]
pub struct SupportedToken {
    // 对应的平台
    pub platform: Pubkey,

    // 代币的 Mint Account
    pub mint_account: Pubkey,

    // 添加时间戳
    pub added_at: i64,

    pub bump: u8,

## 代币添加指令的账户上下文

```rust
#[derive(Accounts)]
pub struct AddSupportedToken<'a> {
    #[account(
        has_one = authority,
        seeds = [b"platform"],
        bump = platform.bump
    )]
    pub platform: Account<'a, Platform>,

    #[account(
        init,
        payer = authority,
        space = 8 + SupportedToken::INIT_SPACE,
        seeds = [b"supported token", platform.key().as_ref(), mint_account.key().as_ref()],
        bump
    )]
    pub supported_token: Account<'a, SupportedToken>,

    // 代币 Mint Account
    pub mint_account: Account<'a, Mint>,

    // 平台的 ATA
    #[account(
        init_if_needed,
        payer = authority,
        associated_token::mint = mint_account,
        associated_token::authority = platform
    )]
    pub platform_treasury_ata: Account<'a, TokenAccount>,

    #[account(mut)]
    pub authority: Signer<'a>,

    // Solana 的内置系统程序，用来创建账户、SOL 转账等
    pub system_program: Program<'a, System>,

		// Solana 的代币标准程序
    pub token_program: Program<'a, Token>,

    // Solana 的 Associated Token Program，用来创建 ATA
    pub associated_token_program: Program<'a, AssociatedToken>,
}
```

- `pub platform: Account<'a, Platform>`
    
    平台账户。
    
    - `has_one = authority`
        
        `platform` 这个账户中的 `authority` 字段必须等于下面 `authority` 字段。
        
    - `seeds = [b"platform"]`
        
        `platform` 这个账户的地址是由固定种子 `"platform"` 和 program id 派生出来的 PDA。
        
    - `bump = platform.bump`
        
        这个 PDA 的 bump 值等于 `platform` 账户的 `bump` 字段的值。
        
- `pub supported_token: Account<'a, SupportedToken>`
    
    要创建的 `SupportedToken` 账户。
    
    - `init`
        
        表示如果账户不存在则创建。如果已存在则报错。
        
    - `payer = authority`
        
        创建账户的租金由 `authority` 支付。
        
    - `space = 8 + SupportedToken::INIT_SPACE`
        
        为账户分配的字节大小。
        
        `8` 是 Anchor 账户 `discriminator` 的固定长度，后面是结构体的空间。
        
    - `seeds = [b"supported token", platform.key().as_ref(), mint_account.key().as_ref()]`
        
        由 平台地址 和 Mint 地址 派生出唯一的 `SupportedToken` 账户。每个平台针对每个 Mint 只能有一个 `SupportedToken` 账户。
        
        `platform.key().as_ref()` 
        
        - `.key()` 返回的是一个 Pubkey，然后 `.as_ref()` 把它变成字节切片 `&[u8]`，用于 PDA seeds。
    - `bump`
        
        Anchor 会自己推导 bump 并校验。
        
- `pub mint_account: Account<'a, Mint>`
    
    要添加的 Mint Account。Anchor 会自动帮你反序列化这个账户，确保它真的是一个合法的 SPL Mint Account，如果传入的地址不是一个合法的 Mint Account，指令会直接失败。
    
    `Mint` 是一个结构体，通过 `anchor_spl::token::Mint` 引入。为此需要在程序中添加依赖，首先进入 programs/auction 目录，然后安装依赖：
    
    ```bash
    cargo add anchor-spl
    ```
    
    然后在其 Cargo.toml 中的依赖中就多了一项：
    
    ```toml
    [dependencies]
    anchor-lang = "0.31.1"
    anchor-spl = "0.31.1"
    ```
    
    `#[derive(Accounts)]` 这个宏会遍历其所在的结构体中的每一个账户字段，收集它们的类型信息，写进 **IDL** 文件中。添加完依赖之后，还需要将 `anchor-spl/idl-build` 这个 feature 放到 Cargo.toml 中，否则会报错：
    
    ```toml
    [features]
    default = []
    cpi = ["no-entrypoint"]
    no-entrypoint = []
    no-idl = []
    no-log-ix-name = []
    idl-build = ["anchor-lang/idl-build", "anchor-spl/idl-build"]
    
    [dependencies]
    anchor-lang = "0.31.1"
    anchor-spl = "0.31.1"
    ```
    
    - `idl-build = ["anchor-lang/idl-build", "anchor-spl/idl-build"]`
        
        等式左侧的 ****`idl-build` 定义了当前 crate 的一个 feature 名字，右边的数组表示这个 feature 依赖于哪些别的 feature。如果启用了 `idl-build` 这个 feature，也要启用 `anchor-lang` crate 的 `idl-build` feature 和 `anchor-spl` crate 的 `idl-build` feature。
        
        - `anchor-lang/idl-build` 指的是 anchor-lang crate 在它的 Cargo.toml 里定义的一个名字为 idl-build 的 feature，这个 feature 被开启后会把 IDL 生成相关的代码编译进来，从而支持 IDL 的生成。
        - `anchor-spl/idl-build` 也是一样的。
- `pub platform_treasury_ata: Account<*'a*, TokenAccount>`
    
    由 `authority` 拥有的、用于存放 `mint_account` 代币的 ATA。
    
    `init_if_needed`
    
    如果账户不存在，就自动创建；如果已存在，就直接复用。需要在 Cargo.toml 中开启 `init-if-needed` feature。
    
    ```toml
    anchor-lang = { version = "0.31.1", features = ["init-if-needed"] }
    ```
    
    `payer = authority`
    
    创建账户的租金由 `authority` 支付。
    
    `associated_token::mint = mint_account`
    
    指定 这个 ATA 的代币。
    
    `associated_token::authority = platform`
    
    指定这个 ATA 的 **owner**。
    
- `pub authority: Signer<'a>`
    
    调用该指令的签名者。
    
- `system_program: Program<'a, System>`
    
    Solana System Program。当创建账户时，Anchor 内部会调用 System Program 来分配空间和转账租金等。
    
- `pub token_program: Program<*'*a, Token>`
    
    SPL Token Account 的 **owner**。
    
- `pub associated_token_program: Program<*'a*, AssociatedToken>`
    
    负责推导出 ATA 地址，然后在内部调用 System Program 和 Token Program 进行账户创建。
    

## 代币添加指令

```rust
pub fn handler(ctx: Context<AddSupportedToken>) -> Result<()> {
    let supported_token = &mut ctx.accounts.supported_token;

    supported_token.platform = ctx.accounts.platform.key();
    supported_token.mint_account = ctx.accounts.mint_account.key();
    supported_token.added_at = Clock::get()?.unix_timestamp;
    supported_token.bump = ctx.bumps.supported_token;

    emit!(TokenAdded {
        platform: supported_token.platform,
        mint: supported_token.mint_account,
        added_at: supported_token.added_at,
    });

    Ok(())
}
```

- `supported_token.bump = ctx.bumps.supported_token`
    
    每个 PDA（Program Derived Address）都有一个 bump 值（保证生成地址时满足 `find_program_address` 的要求）。`ctx.bumps.supported_token` 是 Anchor 自动收集的 PDA bump。存到账户的 bump 字段中，未来可以直接用来重新推导地址。
    

- `TokenAdded`
    
    定义的 #[event] struct，用于链上日志。
    
    ```rust
    #[event]
    pub struct TokenAdded {
        pub platform: Pubkey,
        pub mint: Pubkey,
        pub added_at: i64,
    }
    ```
