# 初始化代码

> 公开版说明：原文中的助记词和私钥示例已移除。请按教程在本地生成测试钱包，并替换代码中的占位内容。

```tsx
    // Configure provider
    anchor.setProvider(anchor.AnchorProvider.env());
    // The Auction Program instance
    const program = anchor.workspace.auction as Program<Auction>;

    /* -----BEGIN: 每次重置环境，这里都要修改----- */

    // 平台支持的结算代币
    const mintPk = new anchor.web3.PublicKey("D4qHfYe6MDh1cfR6ikWDYqhFNgBoKMVVtX8Trs27C1Xp");

    // 拍品 NFT Mint Account，用于英式拍卖
    const nftPk = new anchor.web3.PublicKey("AyAN3SQGYgxQUjuKpzWSS49oQD1EWhLyN1BV5RrebcUx");

    // 拍品 FT Mint Account，用于荷兰拍卖
    const ftPk = new anchor.web3.PublicKey("3GCL8PjhJWmvHHyLnsgB4kBPgUh7Qnapo6xFJAt4sNYm");

    /* -----END: 每次重置环境，这里都要修改----- */

    // 平台账户
    let [platformPda, _platformBump] = anchor.web3.PublicKey.findProgramAddressSync(
        [Buffer.from("platform")],
        program.programId
    );

    // 平台账户持有结算代币的 ATA
    const platformTreasuryAta = anchor.utils.token.associatedAddress({
        mint: mintPk,
        owner: platformPda,
    });

    // 用于存储平台所支持代币的账户
    const [supportedTokenPda, _supportedTokenBump] = anchor.web3.PublicKey.findProgramAddressSync(
        [
            Buffer.from("supported token"),

    // 拍卖行的管理员账户
    // 直接把 JSON 文件中的内容复制到这里
```

- `anchor.setProvider(anchor.AnchorProvider.env())`
    
    使用 Solana CLI 的配置文件来创建一个 Provider。我们这里在 localhost 中进行测试，因此可以使用 `solana config set -u localhost` 设置一下该文件中的网络，最终的配置文件内容为：
    
    ```
    Config File: /Users/paulliu/.config/solana/cli/config.yml
    RPC URL: http://localhost:8899 
    WebSocket URL: ws://localhost:8900/ (computed)
    Keypair Path: /Users/paulliu/.config/solana/id.json 
    Commitment: confirmed
    ```
    

- `anchor.web3.PublicKey.findProgramAddressSync`
    
    计算平台账户的 PDA 和 bump，语法如下：
    
    ```tsx
    const [pda, bump] = PublicKey.findProgramAddressSync(seeds, programId);
    ```
    
    - `seeds` 是一个数组，类型是 `Array<Buffer | Uint8Array>`。`Buffer` 是 Node.js 提供的一个 字节数组类，继承自 `Uint8Array`。该数组把其中的每个元素按顺序拼接，形成一个大字节串。
    - `programId` 是链上程序的公钥。

`[Buffer.from("platform")]`

- `Buffer.from()` 返回的类型是 `Buffer`。这行代码把 `"platform"` 转成字节数组 `[112,108,97,116,102,111,114,109]`，每个字符按 UTF-8 编码成字节。

`platformPda.toBuffer()`

- `platformPda` 是 PublicKey 类型，其内部存的是 32 字节数组，除了可以使用 `.toBase58()` 将其表示为 base58 字符串，也可以使用 `.toBuffer()` 直接返回这个 32 字节的数组。

平台可以支持如 USDT, USDC 等代币，我们可以直接使用这些代币的 Mint Account。但需要注意的是 USDT, USDC 在不同网络上的发行情况，USDT 仅在 `mainnet` 上发行，而 USDC 在 `mainnet` 和 `devnet` 上发行。如果我们使用的网络上没有发行这些代币，那我们就无法使用。

由于我们测试使用的网络是 `localhost`，USDT, USDC 都是没有的，我们的测试代码中是先通过命令行创建了结算代币，然后直接在测试中使用的。

也可以直接在代码创建一个临时的 SPL Mint Account。

- `createMint`
    
    `@solana/spl-token` 里提供的一个工具函数，作用是在链上创建并初始化一个新的 SPL Token Mint 账户。
    
    ```tsx
    createMint(
        connection: Connection,
        payer: Signer,
        mintAuthority: PublicKey,
        freezeAuthority: PublicKey | null,
        decimals: number,
        keypair = Keypair.generate(),
        confirmOptions?: ConfirmOptions,
        programId = TOKEN_PROGRAM_ID,
    ): Promise<PublicKey>
    ```
    
    `connection: Connection`
    
    - 和 Solana 节点交互的连接对象。
    
    `payer: Signer`
    
    - 谁来付新建账户的租金和手续费。
    
    `mintAuthority: PublicKey`
    
    - **铸币权限地址**。
    - 只有这个地址才能调用 `mintTo` 给某个账户增发代币。
    
    `freezeAuthority: PublicKey | null`
    
    - **冻结权限地址**。
    - 拥有这个权限的账户可以冻结 / 解冻某个 Token Account。
    
    `decimals: number`
    
    - 代币的小数位数，决定显示精度。
    - 比如 `decimals = 9`：1 token = 1,000,000,000 最小单位（和 SOL 一样）。
    
    `keypair = Keypair.generate()`（可选）
    
    - 如果你想自己指定 mint 地址，可以传一个 `Keypair`。否则会帮你生成一个地址。
    
    `confirmOptions?: ConfirmOptions`（可选）
    
    - `ConfirmOptions` 是来自 `@solana/web3.js` 里的类型定义：
        
        ```tsx
        export interface ConfirmOptions {
          commitment?: Commitment;
          preflightCommitment?: Commitment;
          skipPreflight?: boolean;
          maxRetries?: number;
        }
        ```
        
        `commitment`
        
        - 指定交易确认的级别，值有 `"processed" | "confirmed" | "finalized"`。
        - 默认通常是 `"confirmed"`。
        
        `preflightCommitment`
        
        - 发送交易前，RPC 节点会进行预检（simulate），这里控制预检用的 commitment。
        - 常见值同上。
        - 默认是 `"processed"`。
        
        `skipPreflight`
        
        - 是否跳过预检模拟（默认 `false`）。
        - 设为 `true` 可以省时间，但可能发出无效交易。
        
        `maxRetries`
        
        - 重试次数，默认 5。
        - 如果 RPC 节点繁忙，可以调大。

        💡
        
        当你把构造好的交易发送到网络上时，默认会先在 RPC 节点上做一次模拟执行（simulateTransaction），这个过程就叫 **preflight**。它不会真正上链，只是快速跑一遍，检查这笔交易是否看上去可行。

    `programId = TOKEN_PROGRAM_ID`（可选）
    
    - Token Program 的地址。
    - 默认是老的 `TOKEN_PROGRAM_ID`。
    - 如果你要用 Token-2022 功能，需要传 `TOKEN_2022_PROGRAM_ID`。
