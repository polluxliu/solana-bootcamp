# 拍卖相关的账户模型和指令设计

# 拍卖活动

这里我们使用同一个账户模型来支持英式拍卖和荷兰拍卖，通过其中的 `auction_type` 字段来区分。英式拍卖专用的字段使用 `english_` 前缀，荷兰拍卖专用的字段使用 `dutch_` 前缀。

## 账户模型

```rust
#[account]
#[derive(InitSpace)]
pub struct Auction {
    // 所属拍卖行
    pub auction_house: Pubkey,

    // 拍卖发起人（卖家）
    pub seller: Pubkey,

    // 拍品 Mint Account
    pub asset_mint_account: Pubkey,

    // 拍品托管 ATA
    pub escrow_asset_ata: Pubkey,

    // 出价资金托管账户
    pub escrow_bid_ta: Pubkey,

    // 拍品数量（FT 时可能 >1；NFT 时是 1）
    pub amount: u64,

    // 起拍价（以结算代币计价）。荷兰拍卖时 = 初始价格
    pub start_price: u64,

    // 开始时间戳
    pub start_time: i64,

    // 结束时间戳，软结束机制，可自动延长。荷兰拍卖时固定
    pub end_time: i64,

    // 绝对结束时间戳。
    pub end_time_deadline: i64,

    // 拍卖类型（0=英式，1=荷兰，后续可扩展）
    pub auction_type: u8,

    // 拍卖 ID
    pub auction_id: u64,

    // PDA bump
    pub bump: u8,

    //
    // 英式拍卖
    //

    // 底价（reserve price），0 表示无底价（以结算代币计价）
    pub english_reserve_price: u64,

    // 当前最高出价（以结算代币计价）
    pub english_highest_bid: u64,

    // 当前最高出价者
    pub english_highest_bidder: Pubkey,

    //
    // 荷兰拍卖
    //

    // 每次降价的时间间隔（秒）
    pub dutch_price_drop_interval: i64,

    // 每次降价的幅度
    pub dutch_price_drop_amount: u64,

    // 最低价格
    pub dutch_end_price: u64,

    //
    // 以下三个字段由结算命令进行更新
    //

    // 拍卖状态，None = 没有结果（尚未开始或正在进行），Some = 已有结果（成交或流拍）
    pub status: Option<AuctionStatus>,

    // 成交价格，流拍时 = 0
    pub final_price: u64,

    // 成交买家，流拍时 = Pubkey::default()
    pub buyer: Pubkey,
}
```

`start_price: u64`

起始价格。

- 英式拍卖：起拍价。
- 荷兰拍卖：初始价格（最高价）。

`escrow_bid_ta`

出价资金托管账户。

- 对于英式拍卖，存放当前最高出价的资金。该账户里始终只存储当前最高出价的资金，每次有人出更高价，合约把旧的最高价退回给其竞拍者。
- 对于荷兰拍卖，存放买断的资金。

`escrow_asset_ata`

拍品托管账户。存放卖家拍卖的标的物（NFT 或 FT），确保拍品不会在拍卖过程中被卖家转走。

`end_time / end_time_deadline`

该模型中使用了两个结束时间戳：`end_time` 和 `end_time_deadline`。

`end_time_deadline` 的值是程序通过下面的公式计算出来的：

$$
end\_time\_deadline = start\_time + 平台最大允许时长
$$

- 在线下的英式拍卖中，主持人会在没有更高出价时喊 **第一次、第二次、第三次，成交！**这是一种人性化的缓冲，给潜在买家最后一次出价机会。但链上拍卖中没有主持人，所有逻辑是通过合约来决定的。为了防止最后一秒抢拍，我们这里引入了软结束机制。
    - 如果在 `end_time` 前的某个时间段（如 1 分钟），有人有效出价（高于当前最高出价的出价），则自动把 `end_time` 往后推迟一个时间段（如 1 分钟）：
        
        $$
        end\_time = end\_time + 1 min
        $$
        
        如果一直有人在 `end_time` 前的某个时间段内有效出价，就会多次触发延长，但 `end_time` 不能超过 `end_time_deadline`，当 `end_time` 超过了 `end_time_deadline` 就强制结束。
        
    - 在 `end_time` 以内，如果没有人触发延长，就在 `end_time` 结束。

- 在荷兰拍卖中，`end_time_deadline` 也同样用于兜底，防止有人设置了不合理的 `end_time`。end_time 的设置不能随意，需要满足：
    
    $$
    end\_time\geq start\_time+\frac{(start\_price-dutch\_end\_price)}{dutch\_price\_drop\_amount} * dutch\_price\_drop\_interval
    $$
    
    这样才能确保有足够的时间来覆盖整个荷兰拍卖的过程。但如果 end_time 设置的太大，会由 `end_time_deadline` 进行约束。
    

`english_`

对于英式拍卖，在竞拍过程中会有一系列的出价，但我们只把最高出价 `english_highest_bid` 和最高出价人 `english_highest_bidder` 存储在了这个账户中，其他出价不写到链上，而是通过 **event** 通知客户端。因为不用保存每次出价，节省链上存储空间，租金更低。但不足之处是客户端需要依赖事件流来恢复完整的出价历史，如果用户掉线或错过事件，就需要从外部索引服务重放。这种在链上只保留最小必要状态而历史用事件或 off-chain indexer 存储是一个常见做法。

`english_reserve_price` 是保留价，低于这个价即使有人出价也算流拍。设置为 0 表示无保留价。在 **结算指令** 中使用这个值来判断是否流拍。

`dutch_`

- `dutch_price_drop_interval` 是每次降价的时间间隔（秒），控制降价节奏。例如 `60` 表示每 60 秒降一次。
- `dutch_price_drop_amount` 是每次下降的价格幅度。例如 `100` 表示每次降价减 100。
- `dutch_end_price` 是价格下降的下限。无论如何，价格不会低于这个值。当价格降到该值时，拍卖维持该值直到结束。

以下三个字段用于拍卖活动的状态检索。

`pub status: Option<AuctionStatus>`

拍卖已结束。可以是已成交或者流拍。拍卖活动创建的时候值为 `None`。

```rust
#[derive(InitSpace, AnchorSerialize, AnchorDeserialize, Clone, PartialEq, Eq)]
pub enum AuctionStatus {
    Settled, // 已成交
    Unsold,  // 流拍
}
```

`pub final_price: u64` 

最终的成交价。如果流拍则为 0。

`pub buyer: Pubkey` 

最终的买家。如果流拍则为占位符 `Pubkey::default()`。

## 拍品创建指令的账户上下文

```rust
#[derive(Accounts)]
pub struct CreateAuction<'a> {
    // 平台账户
    pub platform: Account<'a, Platform>,

    // 拍卖行管理员账户
    /// CHECK: 仅用作 PDA seeds
    pub auction_house_authority: UncheckedAccount<'a>,

    // 拍卖行结算代币 Mint Account
    // 下面的 auction_house 账户中存储有结算代币的公钥
    // 但 escrow_bid_account 账户的约束中需要传递 Mint Account 而不是公钥
    #[account(
        constraint = auction_house.settlement_mint == settlement_mint_account.key()
    )]
    pub settlement_mint_account: Account<'a, Mint>,

    // 拍卖行账户
    #[account(
        mut,
        has_one = platform,
        seeds = [b"auction house", platform.key().as_ref(), auction_house_authority.key().as_ref()],
        bump = auction_house.bump
    )]
    pub auction_house: Account<'a, AuctionHouse>,

    // 卖家账户
    #[account(mut)]
    pub seller: Signer<'a>,

    // 拍品（NFT,FT）的 Mint Account
    pub asset_mint_account: Account<'a, Mint>,

    // 卖家 ATA
    #[account(
        mut,
        constraint = seller_asset_ata.owner == seller.key(),
        constraint = seller_asset_ata.mint == asset_mint_account.key(),
    )]
    pub seller_asset_ata: Account<'a, TokenAccount>,

    // 拍品托管 ATA
    #[account(
        init,
        payer = seller,
        associated_token::mint = asset_mint_account,
        associated_token::authority = auction
    )]
    pub escrow_asset_ata: Account<'a, TokenAccount>,

    // 出价托管 Token Account
    #[account(
        init,
        payer = seller,
        seeds = [b"escrow", auction.key().as_ref()],
        bump,
        token::mint = settlement_mint_account,
        token::authority = auction
    )]
    pub escrow_bid_ta: Account<'a, TokenAccount>,

    // 拍卖账户
    #[account(
        init,
        payer = seller,
        space = 8 + Auction::INIT_SPACE,
        seeds = [b"auction", auction_house.key().as_ref(), auction_house.next_auction_id.to_le_bytes().as_ref()],
        bump
    )]
    pub auction: Account<'a, Auction>,

    // 系统程序账户
    pub system_program: Program<'a, System>,

    // Token 程序账户
    pub token_program: Program<'a, Token>,

    // Associated Token 程序账户
    pub associated_token_program: Program<'a, AssociatedToken>,
}
```

- `pub platform: Account<*'a*, Platform>`
    
    顶层的平台账户，用于校验 `auction_house`。Anchor 会验证传进来的 `platform` 账户能否解码成你定义的 `Platform` 结构。同时在下面的 `auction_house` 的约束里有 `has_one = platform`，这保证了传进来的拍卖行隶属于这个平台。
    
- `pub auction_house_authority: UncheckedAccount<*'a*>`
    
    拍卖行管理员账户，用于校验 `auction_house`。类型用 `UncheckedAccount`，表示 Anchor 不会对这个字段自动做账户验证，也不会对其 `data` 字段进行序列化和反序列化，直接给你一个 **原始账户引用 (`AccountInfo`)**，你自己决定怎么用。你可以：
    
    - `.key()` → 取它的公钥 (`Pubkey`)
    - `.lamports()` → 读余额（SOL）
    - `.owner` → 看它归属哪个 program
    - `.data` → 原始字节数组（不会自动解码）

    💡
    
    在 Solana 的 运行时 (solana_program crate) 里，每个指令调用时，程序会收到一组账户参数。这些账户在 Rust 里就是用 **`AccountInfo`** 来表示的。而 **Anchor 中的所有账户类型最终都是 `AccountInfo` 的封装**。

- `pub settlement_mint_account: Account<*'a*, Mint>`
    
    拍卖行的结算代币。下面的 `auction_house` 账户中存储有结算代币的公钥，但下面的 `escrow_bid_account` 账户的约束中在用到这个结算代币时需要传递 Mint Account 而不是公钥，因此这里额外添加了这么一个账户。在客户端传递该账户时，需要首先从链上的拍卖行账户中查询到其结算代币的公钥。
    
- `pub auction_house: Account<*'a*, AuctionHouse>`
    
    拍卖行账户。用于校验当前拍卖确实属于合法的拍卖行并生成拍卖账户。注意这里使用了 `mut` 约束，是因为每添加一个拍卖活动，拍卖行账户中的 `next_auction_id` 都会增加。
    
- `pub seller: Signer<'a>`
    
    卖家账户，拍卖的发起人。没有它的签名，整个指令不会执行。用于支付链上交易费（需客户端明确指定为 fee-payer）以及新建账户的租金。
    
- `pub asset_mint_account: Account<*'a*, Mint>`
    
    SPL Token 的 Mint 账户，可能是 NFT 也可能是 FT，用于标识拍卖的具体资产。Anchor 会解码并确认是一个合法的 Mint Account。
    
- `pub seller_asset_ata: Account<*'a*, TokenAccount>`
    
    卖家持有代币的 TokenAccount。从这里转移拍品到托管账户。
    
    `constraint =` 用于添加 **自定义校验逻辑**，允许你写下布尔表达式作为条件，用来告诉 Anchor 在进入指令之前，检查账户是否满足某些逻辑条件：
    
    - 这个账户的 `owner` 字段必须等于 `seller.key()`
    - 这个账户的 `mint` 字段必须等于 `asset_mint_account.key()`
    - ~~这个账户的 `amount` 字段必须大于 0~~ （放到指令中去做验证）
    
    这里也可以使用 `associated_token::` 语法：
    
    ```rust
    associated_token::mint = asset_mint_account,
    associated_token::authority = seller,
    ```
    
    其相当于
    
    ```rust
    constraint = seller_asset_ata.key() == get_associated_token_address(&seller.key(), &asset_mint_account.key()),
    constraint = seller_asset_ata.mint == asset_mint_account.key(),
    constraint = seller_asset_ata.owner == seller.key()
    ```
    
    注意 `associated_token::` 只关心 ATA 地址、mint、owner 三者的校验，余额检查这种逻辑（`amount > 0` 或 `amount >= args.amount`）**不能** 用 `associated_token::` 语法。
    
    `constraint = <布尔表达式> @ ErrorCode::SomeVariant`
    
    - 如果 `<布尔表达式>` 不成立，就返回 `ErrorCode::SomeVariant`。
    - 如果不写 `@ ...`，Anchor 会返回一个默认错误 "Constraint violation"。
    
- `pub escrow_asset_ata: Account<*'a*, TokenAccount>`
    
    为当前拍品创建一个托管账户（ATA），由当前的拍卖账户作为该 ATA 的 owner，由 `seller` 支付账户租金。拍卖期间拍品将被锁定在这个账户中，拍卖结束时，程序根据结果（成交 / 流拍）把资产从中转移给买家或退还给卖家，这个托管账户也将被关闭，账户的租金会退还给 `seller`。注意，在创建拍卖账户的时候，就已经将拍品转入到了这个托管账户中。
    
    如果创建的是一个 自定义数据账户（例如 `Account<'info, Auction>`），你必须指定 `space`，因为 Solana 需要在创建账户时知道要分配多少字节的存储空间。但 SPL Token Program 定义了 Token Account 的数据结构，大小是固定的 165 字节，因此创建 Token Account 时不需要 `space`。
    
- `pub escrow_bid_ta: Account<*'a*, TokenAccount>`
    
    创建一个出价资金托管账户（Token Account），将当前最高出价锁定在这个账户中。
    
    - 如果有人出更高价，旧的最高出价人的资金将退回。
    - 如果拍卖结束，这里存储的赢家资金将由合约转发给卖家（扣平台费、拍卖行费等）。
    
    这里我们使用了普通的 Token Account 而不是 ATA，是因为要避免当 $asset\_mint\_account=settlement\_mint\_account$ 时与 `escrow_asset_ata` 的冲突。注意，这里的约束多了 `seeds` 和 `bump`。
    
- `pub auction: Account<*'a*, Auction>`
    
    创建一个拍卖账户，用来存储一次拍卖活动的数据，如起拍价等，由 `seller` 支付账户租金。使用当前拍卖行账户的公钥和 `next_auction_id` 作为种子，每次添加一个拍卖活动，`next_auction_id` 都会自增 1。
    
    `auction_house.next_auction_id.to_le_bytes().as_ref()`
    
    - `.to_le_bytes()` 返回的是 `[u8; 8]`（数组），`.as_ref()` 会把 `[u8; 8]` 转换成 `&[u8]`。
    - Rust 的整数序列化 API 提供了 `to_le_bytes()`（小端）、`to_be_bytes()`（大端）、`to_ne_bytes()`（本地字节序）。
    - Anchor / Solana 并不强制必须小端或大端，只要 **你在生成和验证 PDA 时保持一致** 就行。
    - 为什么这里使用小端序？Rust 本身运行在不同硬件平台，但目前 **主流 CPU（x86、x86-64、ARM64 等）几乎都是小端序**。所以 Rust 社区和大多数库习惯上会用 **`to_le_bytes()`** 来做整数序列化，保证跨平台一致性。

    💡
    
    多字节的数值类型如 `u32 = 0x12345678`，在逻辑上是一个整体，但在内存中需要拆成 4 个字节表示：
    
    - 高位字节 = `0x12`
    - 次高位字节 = `0x34`
    - 次低位字节 = `0x56`
    - 低位字节 = `0x78`
    
    在计算机里，内存是按字节寻址的：
    
    - 每一个字节都有一个唯一的地址；
    - 地址数值从小到大，就是物理上「从低地址到高地址」。
    
    以上 4 个字节在内存中的存储的顺序是由 **CPU 架构** 决定的。
    
    - 小端 CPU（x86 常见）：`78 56 34 12` （低位字节放在低地址）
    - 大端 CPU（少见）：`12 34 56 78` （高位字节放在低地址）
    
    任何编程语言，只要要把多字节数值放到内存里，都会遇到 **大端 / 小端** 的问题。
    
    当我们将其转成字节数组时，可以指定顺序：
    
    ```rust
    let bytes_le = x.to_le_bytes(); // [78, 56, 34, 12]
    let bytes_be = x.to_be_bytes(); // [12, 34, 56, 78]
    ```
    
    就像把它写到纸上，写成 `78 56 34 12` 或 `12 34 56 78`，你可以选写法。
    
    $$
    内存存储顺序（CPU 决定） ≠ 对外展示的字节顺序（你自己控制）。
    $$
    
    需要考虑字节序的类型如下。
    
    整数类型如：
    
    ```rust
    // 这些都有字节序问题，因为它们占用多个字节
    u16, i16   // 2 字节
    u32, i32   // 4 字节  
    u64, i64   // 8 字节
    u128, i128 // 16 字节
    usize, isize // 平台相关（4 或 8 字节）
    ```
    
    浮点类型如：
    
    ```rust
    f32  // 4 字节
    f64  // 8 字节
    ```
    
    **为什么其他类型如字符串类型没有这个问题？**
    
    如字符串 `“abc”` ，默认使用 utf-8 编码，每个字符都是 ASCII，占用 1 个字节，所以该字符串使用 3 个字节表示：
    
    ```rust
    'a' → 0x61
    'b' → 0x62
    'c' → 0x63
    ```
    
    其在内存中是这样的：
    
    ```rust
    地址:   0x1000   0x1001   0x1002
    内容:    0x61     0x62     0x63
    ```
    
    **始终按编码顺序依次存在内存中，从起始地址依次向高地址布局**，各字节无须考虑字节序问题。

    拍卖结束后，这个拍卖账户可以选择 **保留**，作为历史记录，链上可查询。也可以 **关闭**，把租金退还给 `seller`，但链上就无法直接查历史，需要链下服务保存。
    

## 拍品创建指令

```rust
pub fn handler(ctx: Context<CreateAuction>, args: CreateAuctionArgs) -> Result<()> {
    let platform = &ctx.accounts.platform;
    let mint = &ctx.accounts.asset_mint_account;
    let seller_asset_ata = &ctx.accounts.seller_asset_ata;

    // 判断当前 mint 是 NFT 还是 FT
    if mint.decimals == 0 {
        // NFT 校验条件
        // - supply 必须等于 1
        // - mint_authority 必须为 None（不可再增发）
        require!(mint.supply == 1, error::ErrorCode::InvalidNFT);
        require!(mint.mint_authority.is_none(), error::ErrorCode::InvalidNFT);

        // 只能拍卖 1 个
        require!(args.amount == 1, error::ErrorCode::InvalidAmountForNFT);
    } else {
        // FT，拍卖数量必须大于 0
        require!(args.amount > 0, error::ErrorCode::InvalidAmountForFT);
    }
    // 不论是 NFT 还是 FT：卖家的账户余额必须大于等于拍卖数量
    require!(
        seller_asset_ata.amount >= args.amount,
        error::ErrorCode::InsufficientBalance
    );

    // 起拍价必须 > 0
    require!(args.start_price > 0, error::ErrorCode::InvalidStartPrice);

    // 拍卖类型合法
    require!(
        args.auction_type == 0 || args.auction_type == 1,
        error::ErrorCode::InvalidAuctionType
    );

    // 时间必须合理
    require!(
        args.start_time >= Clock::get()?.unix_timestamp,
        error::ErrorCode::StartTimeInPast
    );
    require!(
        args.end_time > args.start_time,
        error::ErrorCode::InvalidAuctionEndTime
    );
    let duration = (args.end_time - args.start_time) as u64;
    // 校验最小值
    require!(
        duration >= platform.auction_duration_min,
        error::ErrorCode::AuctionDurationTooShort
    );
    // 校验最大值
    require!(
        duration <= platform.auction_duration_max,
        error::ErrorCode::AuctionDurationTooLong
    );

    // 计算 end_time_deadline = start_time + auction_duration_max
    let end_time_deadline = args.start_time + platform.auction_duration_max as i64;
    // 确保 end_time 不超过 final_end_time
    require!(
        args.end_time <= end_time_deadline,
        error::ErrorCode::InvalidFinalEndTime
    );

    if args.auction_type == 0 {
        // 英式拍卖
        // 底价必须 ≥ 起拍价
        require!(
            args.english_reserve_price == 0 || args.english_reserve_price >= args.start_price,
            error::ErrorCode::InvalidReservePrice
        );
    } else {
        // 荷兰拍卖
        require!(
            args.dutch_end_price < args.start_price,
            error::ErrorCode::InvalidDutchEndPrice
        );
        require!(
            args.dutch_price_drop_interval > 0,
            error::ErrorCode::InvalidDutchInterval
        );
        require!(
            args.dutch_price_drop_amount > 0,
            error::ErrorCode::InvalidDutchDropAmount
        );

        // 价格总下降幅度 = 起始价 - 结束价
        let total_drop = args
            .start_price
            .checked_sub(args.dutch_end_price)
            .ok_or(error::ErrorCode::NumericalOverflow)?;

        // 要求价格总下降幅度能被 每次降价幅度 整除，这样才能保证价格能精确走到 end_price
        require!(
            total_drop % args.dutch_price_drop_amount == 0,
            error::ErrorCode::DutchDropNotAligned
        );

        // 总共需要降多少次
        let steps = total_drop / args.dutch_price_drop_amount;
        // 这些次数的降价所需的最短时间
        let required_duration = steps
            .checked_mul(args.dutch_price_drop_interval as u64)
            .ok_or(error::ErrorCode::NumericalOverflow)?;

        // 拍卖总时长需要足够覆盖所有降价次数
        require!(
            (args.end_time - args.start_time) as u64 >= required_duration,
            error::ErrorCode::DutchDurationTooShort
        );
    }

    let auction = &mut ctx.accounts.auction;
    let auction_house = &mut ctx.accounts.auction_house;

    // 初始化拍卖账户数据
    auction.auction_house = auction_house.key();
    auction.seller = ctx.accounts.seller.key();
    auction.asset_mint_account = ctx.accounts.asset_mint_account.key();
    auction.escrow_asset_ata = ctx.accounts.escrow_asset_ata.key();
    auction.escrow_bid_ta = ctx.accounts.escrow_bid_ta.key();

    auction.amount = args.amount;
    auction.start_price = args.start_price;
    auction.start_time = args.start_time;
    auction.end_time = args.end_time;
    auction.end_time_deadline = end_time_deadline;

    auction.auction_type = args.auction_type;
    auction.auction_id = auction_house.next_auction_id;
    auction.bump = ctx.bumps.auction;

    // 查询用字段的初始化
    auction.status = None;
    auction.final_price = 0;
    auction.buyer = Pubkey::default();

    if args.auction_type == 0 {
        // 英式拍卖
        auction.english_reserve_price = args.english_reserve_price;
        auction.english_highest_bid = 0;
        auction.english_highest_bidder = Pubkey::default();

        // 荷兰字段设为默认值
        auction.dutch_price_drop_interval = 0;
        auction.dutch_price_drop_amount = 0;
        auction.dutch_end_price = 0;
    } else {
        // 荷兰拍卖
        auction.dutch_price_drop_interval = args.dutch_price_drop_interval;
        auction.dutch_price_drop_amount = args.dutch_price_drop_amount;
        auction.dutch_end_price = args.dutch_end_price;

        // 英式字段设为默认值
        auction.english_reserve_price = 0;
        auction.english_highest_bid = 0;
        auction.english_highest_bidder = Pubkey::default();
    }

    // 将卖家的拍品转入托管账户
    let cpi_accounts = Transfer {
        from: seller_asset_ata.to_account_info(),
        to: ctx.accounts.escrow_asset_ata.to_account_info(),
        authority: ctx.accounts.seller.to_account_info(),
    };
    let cpi_tx = CpiContext::new(ctx.accounts.token_program.to_account_info(), cpi_accounts);
    transfer(cpi_tx, auction.amount)?;

    // 更新 auction_house.next_auction_id
    // auction_house.next_auction_id += 1;
    auction_house.next_auction_id = auction_house
        .next_auction_id
        .checked_add(1)
        .ok_or(error::ErrorCode::NumericalOverflow)?;

    Ok(())
}
```

- `args: CreateAuctionArgs`
    
    非账户上下文参数。
    
    ```rust
    #[derive(AnchorSerialize, AnchorDeserialize)]
    pub struct CreateAuctionArgs {
        pub amount: u64,      // 拍品数量（FT 时可能 >1，NFT 为 1）
        pub start_price: u64, // 起拍价。荷兰拍卖时是初始价
        pub start_time: i64,  // 开始时间戳
        pub end_time: i64,    // 结束时间戳
        pub auction_type: u8, // 0=英式，1=荷兰
    
        // 英式拍卖专用
        pub english_reserve_price: u64, // 底价（0 表示无底价）。荷兰拍卖时传 0
    
        // 荷兰拍卖专用
        pub dutch_price_drop_interval: i64, // 每次降价间隔
        pub dutch_price_drop_amount: u64,   // 每次降价幅度
        pub dutch_end_price: u64,           // 最低价
    }
    ```
    

- `require!`
    
    这里注意要区分 NFT 和 FT。对于 NFT：
    
    - 除了 `decimals == 0` 和 `supply == 1`，还额外检查 `mint_authority.is_none()`，保证不可再增发。
    - `args.amount` 必须等于 `1`。
    
    关于起拍价和保留价，要么不设保留价（=0），要么设的保留价 ≥ 起拍价。起拍价是拍卖一开始的最低出价门槛，保证竞拍从一个合理水平起步。保留价是拍卖必须达到的最低成交价，否则拍卖流拍，用于保护卖家利益，避免以过低价格成交。
    
- `auction.english_highest_bidder = Pubkey::default();`
    
    返回 `Pubkey` 类型的默认值。初始化时没有出价人，就把最高出价人设置成一个占位符地址，这个特殊的地址经常被叫做 **null address**。
    
    `Pubkey` 在 Solana SDK 里就是一个 32 字节的数组：
    
    ```rust
    pub struct Pubkey([u8; 32]);
    ```
    
    `Default` 实现会返回全零数组：
    
    ```rust
    Pubkey([0u8; 32])
    ```
    
    32 字节全 0 的公钥的 Base58 字符串为 `11111111111111111111111111111111`。
    
- `auction_house.next_auction_id += 1` 的问题
    
    直接 `+= 1` 在 Rust 里是安全的运算，但有一个隐患，如果 `next_auction_id` 是 `u64`，理论上它可能达到 `u64::MAX`，再 `+1` 就会发生 **整数溢出**。
    
    - `checked_add(1)`：
        - 如果没溢出 → 返回 `Some(新值)`。
        - 如果溢出 → 返回 `None`。
    - `.ok_or(ErrorCode::NumericalOverflow)?`：
        - 如果是 `None`，就返回一个明确的 `NumericalOverflow` 错误，终止交易。
        - 如果是 `Some(x)`，取出值后赋给 `auction_house.next_auction_id`。
