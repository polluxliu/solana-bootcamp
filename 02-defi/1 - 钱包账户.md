# 1 - 钱包账户

使用下面的命令创建一个钱包，因为是测试，该命令中添加了 `--no-bip39-passphrase`。

```bash
solana-keygen new --outfile ./my-wallets/test-wallet-1.json --no-bip39-passphrase
```

命令执行后，输出的公钥为：`74arGmnMtjNcK5izbBgdtfdNuPRRRBzEWq8UMosrswWP`。

在本地或 Phantom 创建钱包，本质上就是一个密钥对，**还没有被记录在链上**，是“未激活”状态。只有 **首次收到交易** 时才会在链上创建并激活。对于新创建的钱包，在 Solana 中称之为 **unfunded**，有多种翻译，比如未激活、未初始化、无资金，不管怎么称呼，unfunded 指的是还 **未上链** 的账户。对于上面创建的这个 unfunded 账户，执行下面的命令：

```bash
solana account 74arGmnMtjNcK5izbBgdtfdNuPRRRBzEWq8UMosrswWP
```

会返回如下：

```bash
Error: AccountNotFound: pubkey=CXMJ89kDWjooEaUKCGDuw3vLubQ5HPVNMJLnWwz96MYd
```

考虑一个场景，Bob 要给 Alice 转账。Alice 将其新创建的钱包公钥给 Bob，由于 Alice 的钱包还没有被激活，当 Bob 给 Alice 转账 SOL 时，Bob 创建的交易必须包含一条指令，用于在网络上创建 Alice 的钱包账户。因此 Bob 需要为这笔交易需要支付两个费用：

- **交易费 (Transaction Fee)**：这是网络处理和验证交易的成本，金额非常小，通常是几分钱的零头。交易费由 Bob 的钱包单独支付，并不在要转账的金额中。
- **免租押金 (Rent-Exempt Deposit)**：这是必须存入新账户的最小 SOL 数额，用来让账户达到“免租”状态，从而保证它能持久地存在于区块链上。

假如 Bob 发送 10 SOL 给 Alice，转账金额 10 SOL 将被用于两个目的：

- **支付免租押金 (rent-exempt deposit)**：这是账户存在于区块链上所需的最低 SOL 数额。这不是被消耗掉的费用，而是留存在你账户余额中的一部分。
- **转入剩余余额**：10 SOL 的其余部分直接存入你的账户。

Alice 的钱包的最终余额就是 Bob 转出的 **完整 10 SOL**，其中包含了作为免租押金的一部分。也就是说 **免租押金不是发起方额外掏钱，而是包含在转账金额里的**。

下面的命令用于从 **当前钱包** 中发送 SOL 到目标钱包：

```bash
solana transfer <RECIPIENT> <AMOUNT>
```

- `<RECIPIENT>`：接收方的地址（公钥字符串）。
- `<AMOUNT>`：要转账的数量，默认单位是 **SOL**（而不是 lamports）。

为了防止无意间向不存在的账户发送资金，Solana 默认不允许向 **unfunded** 账户直接转账。此时可以使用 `--allow-unfunded-recipient` 参数，即使接收账户还未 **funded**（上链，初始化），也可进行转账。其实就是说，该参数用于表示发送方愿意为接收方创建其账户并支付免租押金。但仍需要转账的额度不低于 rent-exempt。

下面我们尝试往上面创建的钱包地址中转入 SOL，转账额少于 rent-exempt。为此我们需要知道对于一个钱包账户，其 rent-exempt 是多少。下面的命令用于计算一个账户要存储指定大小的数据时，所需的免租 (rent-exempt) 的最低额。

```bash
solana rent <ACCOUNT_DATA_SIZE>
```

`<ACCOUNT_DATA_SIZE>`：账户数据的大小（以字节为单位）。

对于钱包账户，其本身不存储自定义数据，所以它的数据大小是 **0**。运行下面这个命令：

```bash
solana rent 0
```

其输出为：**`Rent-exempt minimum:** 0.00089088 SOL`

现在我们向这个钱包转入少于 `0.00089088` 的 SOL：

```bash
solana transfer 74arGmnMtjNcK5izbBgdtfdNuPRRRBzEWq8UMosrswWP 0.00001 --allow-unfunded-recipient
```

会报如下错误：

```
Transaction results in an account (1) with insufficient funds for rent;
```

因此，在创建时必须转入 **≥ rent-exempt 最低额度** 的 lamports，否则交易会失败。

💡

新账户要上链，必须至少存入免租押金的额度。

我们往这个钱包地址中转账 1 SOL：

```bash
solana transfer 74arGmnMtjNcK5izbBgdtfdNuPRRRBzEWq8UMosrswWP 1 --allow-unfunded-recipient
```

现在该钱包中有 1 SOL 的余额。执行下面的命令，将该钱包中的 SOL 全部转走：

```bash
solana transfer 3ZoojjwWCgArGREegaQgifwwtZF1EQdid5BjEX5weXah 0.999995 --keypair ./my-wallets/test-wallet-1.json
```

1 SOL 中的 `0.000005` 作为交易费，因此转账额为 `0.999995` 就会使得账户的余额为 0。任何账户一旦余额变为 **0 lamports**，就会被立即标记为 **删除**。当交易确认后，这个账户就会从链上状态中彻底清除。当我们执行完上面的命令后，钱包账户 `74arGmnMtjNcK5izbBgdtfdNuPRRRBzEWq8UMosrswWP` 就又成为了 **unfunded**。

如果转走 SOL 后的余额少于 rent-exempt，交易会报错：

```
Transaction results in an account (0) with insufficient funds for rent
```

💡

账户中的 SOL 可以全部转走。但如果不是全部转走，转走后的余额必须大于 rent-exempt，否则转账交易会被中止。

一个钱包账户就是一对密钥对：

- 公钥（PublicKey） = 钱包地址
- 私钥（SecretKey） = 授权交易的凭证

这对密钥本身与网络环境（localhost / testnet / devnet / mainnet-beta）**没有绑定关系**。同一个钱包可以在不同网络使用，不同的网络各自维护一条独立的账本，**余额和交易历史互不相通**。
